PhilGuard API

A starting point for integrating email protection into your application.

The route and payload below are illustrative placeholders. Confirm the real API contract with your backend before using them.

Quick start

  1. Create a project in your workspace.
  2. Obtain API credentials from the backend.
  3. Store secrets in server-side environment variables.
  4. Send API requests from your server, not browser JavaScript.

Example server request

Illustrative PHP cURL example. Replace host, endpoint and schema with the real backend details.

<?php
$apiKey = getenv('PHILGUARD_API_KEY');
$ch = curl_init('https://YOUR-API-HOST.example/v1/secure-email');
curl_setopt_array($ch, [
  CURLOPT_POST => true,
  CURLOPT_RETURNTRANSFER => true,
  CURLOPT_HTTPHEADER => [
    'Content-Type: application/json',
    'Authorization: Bearer ' . $apiKey
  ],
  CURLOPT_POSTFIELDS => json_encode(['email' => 'customer@example.com'])
]);
$response = curl_exec($ch);
if ($response === false) throw new RuntimeException(curl_error($ch));
curl_close($ch);
echo $response;

Security notes

  • Never place private API keys in frontend code.
  • Use HTTPS for production API communication.
  • Authorize and validate requests on the server.
  • Verify payment callbacks server-side.
  • Obtain independent security and compliance reviews.
